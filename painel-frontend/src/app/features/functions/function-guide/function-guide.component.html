Voltar para Funções
As funções nascem no sistema legado Uma função é um pedaço de código do próprio sistema legado, que lê ou altera uma configuração com as regras e os direitos dele. O painel não tem como criá-la: ele importa o que o sistema legado declara e deixa o gestor aprovar, ativar e vincular cada função a um conhecimento. Esta página descreve o que o painel espera, para que quem implementa saiba exatamente o que entregar.

O caminho de uma função

  1. Implemente a função no sistema legado, seguindo o contrato abaixo.
  2. Declare a função no manifesto do sistema legado.
  3. Em Chaves de acesso, gere uma chave de execução com a URL da API do plugin, configure o hash dela no sistema legado e use Testar conexão.
  4. No painel, em Funções, clique em Importar do sistema legado. A função entra pendente e inativa.
  5. Abra a função, confira a descrição e os parâmetros, aprove e ative.
  6. No cadastro de um conhecimento, vincule a função. Só então o Agente pode considerá-la.

O contrato da API

O painel chama o sistema legado em {URL da API do plugin}, o endereço base onde o sistema legado responde os caminhos abaixo (por exemplo, https://meu-sistema.exemplo/sage/api). Essa URL é cadastrada em Chaves de acesso, junto com a chave de execução, e o botão Testar conexão confere se o plugin responde com aquela chave.

Método e caminho Para quê
GET /manifest Devolve a lista fechada das funções. É o que o botão de importar lê.
POST /functions/{code}/execute Executa uma função da lista. Código que não está na lista responde 404.
GET /ping Opcional. Confirma que a conexão e a chave funcionam.

Autenticação

Toda requisição traz o header X-Sage-Execution-Key com a chave de execução criada em Chaves de acesso. O sistema legado guarda só o SHA-256 dela e compara com o hash da chave recebida. Sem chave configurada, rejeita tudo. Desativar a chave no painel suspende toda execução.

O manifesto

Resposta de GET /manifest, com uma função de exemplo.

{{ manifesto }}
Campo O que é
code Identificador estável, no formato modulo.assunto.acao. Só letras minúsculas, números, ponto e sublinhado.
name Nome mostrado no painel e no cartão de autorização.
description Lida pelo Agente para decidir quando usar a função. Diga quando usar e o que ela devolve. Nas alterações, diga que só se usa depois de consultar e confirmar o valor.
module Nome exato de um módulo já cadastrado no painel. Módulo que não existe faz a importação recusar a função.
operation_type consulta roda sozinha. alteracao só roda depois que o usuário autoriza.
parameters Lista de name, type (string, integer, boolean, date em AAAA-MM-DD ou float), required e description.

A execução

Pedido enviado pelo painel a POST /functions/{code}/execute. 

{{ pedido }}

O campo usuario identifica quem está conversando no sistema legado. Além de id e login, pode trazer perfil_id (perfil ou papel), entidade_id (empresa, filial ou área a que o usuário pertence) e recursivo (se o acesso vale também para as subáreas). Esses três são opcionais: use os que fizerem sentido no seu sistema. Nas funções de alteração, o pedido também traz token_autorizacao.

Regras que toda função precisa seguir

  • Roda com os direitos do usuário informado, nunca com os de um administrador. Abra uma sessão temporária dele durante a execução.
  • Consulta nunca altera nada e devolve pode_alterar: se esse usuário pode alterar aquela configuração, segundo a checagem de direitos do próprio sistema. É o que permite ao Agente propor só o que o sistema aceita.
  • Alteração só executa com token_autorizacao válido: emitido pelo sistema legado quando o usuário clica em Autorizar, de uso único e curta duração, ligado ao usuário e à execução.
  • Confirme a alteração lendo o valor de novo e devolva antes e depois. O sistema pode descartar em silêncio um campo sem direito.
  • Use as classes do próprio sistema, não SQL direto, para valerem as regras de negócio e o histórico. Registre uma nota no histórico do item e uma auditoria da execução.
  • Lista fechada: execute só o que está no manifesto.
  • Valide os parâmetros e confira que o item pertence à empresa, filial ou área que o usuário pode acessar.
