Como o sistema legado usa a chave de chat

O chat fica dentro do sistema legado, mas as perguntas são respondidas aqui. O servidor do sistema legado repassa cada mensagem do usuário para a API abaixo e mostra a resposta. A chave de chat vai só no servidor: nunca a coloque no navegador.

{{ integration()?.api_url ?? 'carregando…' }}
Autenticação
Authorization: Bearer <chave de chat>
Formato
JSON, com Accept: application/json. Limite de {{ integration()?.rate_limit_per_minute ?? 20 }} requisições por minuto por usuário.
Método e caminho Quando chamar
POST /chat/messages O usuário enviou uma pergunta. Abre a conversa, se não houver uma, e devolve a resposta do Agente.
GET /chat/conversations/current?erp_user_id={id} O chat foi aberto: devolve a conversa em andamento do usuário, para mostrar o histórico.
POST /chat/conversations/{id}/close O usuário encerrou a conversa. Corpo: { "erp_user_id": 7 }.
POST /executions/{id}/authorize O usuário clicou em Autorizar numa alteração proposta pelo Agente.
POST /executions/{id}/deny O usuário recusou a alteração. Corpo: só usuario_erp.
O que enviar em cada mensagem 
{{ exemploMensagem }}
Campo O que é
content Obrigatório. O texto que o usuário digitou (até 4000 caracteres).
usuario_erp.id, login Obrigatórios. Quem está conversando, tirado da sessão autenticada do sistema legado, nunca do que o navegador informa. Cada usuário tem uma conversa aberta por vez.
usuario_erp.nome, perfil_id, perfil Opcionais. Nome e perfil (papel) do usuário, para o Agente adequar a resposta ao que ele pode fazer.
usuario_erp.entidade_id, entidade, recursivo Opcionais. Empresa, filial ou área do usuário, e se o acesso vale também para as subáreas.
usuario_erp.interface Opcional. Qual interface do sistema ele usa (texto livre, ex.: portal, administrativo).
pagina Opcional, mas recomendado. O endereço da tela em que o usuário está quando pergunta (até 500 caracteres). Ajuda o Agente a entender a que parte do sistema a dúvida se refere.
pagina_titulo Opcional. O título dessa tela, como o usuário a vê (até 200 caracteres).
O que a API devolve 
{{ exemploResposta }}

Mostre as mensagens de conversation.messages em ordem. Quando uma mensagem do Agente traz em executions uma alteração com "status": "pendente", mostre um cartão com o que será alterado e os botões Autorizar e Recusar. A proposta expira em {{ integration()?.execution_ttl_minutes ?? 10 }} minutos (expires_at).

Autorizar ou recusar uma alteração 
{{ exemploAutorizar() }}

No clique em Autorizar, o próprio sistema legado emite o token_autorizacao: de uso único, curta duração e ligado ao usuário e à execução. O painel repassa esse token na chamada da função de alteração, e o sistema legado só altera se o token for válido. Assim, nenhuma alteração acontece sem um clique real do usuário. A resposta traz a conversa atualizada com o resultado.

Erros

Formato: { "error": { "code": "...", "message": "..." } }

HTTP Quando
401Chave de chat ausente, inválida ou desativada.
404Conversa ou execução que não existe, ou que é de outro usuário.
409Alteração já decidida ou expirada.
422Campo faltando ou inválido.
429Muitas mensagens em pouco tempo. Aguarde e tente de novo.
502O sistema legado não respondeu ao executar uma função.
